# Kino der Toten (local modding fork)

The user's fork of luckeyfaraday/kino-der-toten, a Three.js browser
reconstruction of Black Ops Zombies. The upstream developer guide is
`AGENTS.md`. Read it for the upstream layout and test commands.

## Fork setup

- Branch `custom` holds local work. The `upstream` remote is the original repo; update with `git fetch upstream && git merge upstream/main && git lfs pull`. The `origin` remote is the user's backup fork https://github.com/darkmedic043/kino-der-toten (public, because forks of public repos must be; default branch `custom`). Push `custom` there after committing. LFS objects are shared with the upstream fork network, so pushes upload only new LFS files.
- Served by the Podman quadlet `~/.config/containers/systemd/kino.container` (image `node:24-alpine`, checkout bind-mounted read-only at `/app`, running `.tools/serve.mjs 5190 --lan`) on **port 5190**. Port 5173, the upstream default, is used by the deskpet electron-vite dev server on this host. The server sends `Cache-Control: no-cache`, so file edits show up on a browser refresh without a restart.
- Git LFS is installed as a user binary at `~/.local/bin/git-lfs` (no system package). The LFS assets are about 1 GB.
- Host Node is 20 and upstream wants 24. `npm test` passes on 20 anyway. The container uses 24.
- No system browser is installed. Browser checks use Playwright's headless Chromium in `~/.cache/ms-playwright` with `--use-angle=swiftshader --enable-unsafe-swiftshader`. The upstream `.tools/test-*.mjs` scripts hard-code Windows Chrome paths, so they won't run as-is. Software WebGL is slow: hide the canvas before UI screenshots, and don't render Kino and another map in one browser at the same time.

## Fork-only architecture

- **Main menu** `export/web/home.{html,css,js}` is served at `/` via `KINO_HOME=home.html` (env var read by `.tools/serve.mjs`, set in the quadlet). Kino itself is `/index.html`. Tabs: Play (map browser from `mods/maps.json`), Loadout (weapon thumbnails rendered from world models, stats, bonuses), Character (3D preview), Mods. `maps.html` just redirects to `./#play`.
- **Profile** `profile.js`: shared localStorage profile (`kino.mods.progression`: xp, level, loadout, character, stats), plus unlock rules read from `mods/progression/progression.json`. The menu and the progression mod both use it.
- **Mod loader** `mod-loader.js`: `ModHost` merges data patches (objects merge, arrays replace, `null` deletes, `{add,remove}`, weapon `"extends"` which also sets `baseId`), calls an optional `prepare(data)` from scripts, wraps session/enemies methods to emit events, then runs `setup(api)`. `host.camera` and `host.hideViewmodel` let a mod take over rendering.
- **Custom zombies maps**: `custom-world.js` (the `CustomWorld` class) builds a world from a glTF plus named markers (`PLAYER_SPAWN, ZSPAWN, WINDOW, DOOR, WALLBUY, PERK, BOX, PAP, POWER, CLAYMORE, TRAP, TRAPZONE, TELEPORT, TPDEST, EGG`); glTF lights are scaled by scale² for the inch units and `POWERLIGHT_*` lights follow the power; dog rounds fade in fog; unusable markers go to `world.warnings`, which is shown on the map's start menu. It exposes the same interface as upstream `world.js`, so upstream `Enemies`, `MysteryBox` (fed stand-in `data.entities`), `Powerups`, `PerkDrink` and `KinoFeatures` run unchanged. The navmesh is generated in the browser with `vendor/recast-generators.mjs` (a copy of `@recast-navigation/generators` 0.43.1 in the importmap), tiled so door blocking (poly flags) stays local. `zombies.{html,js,css}` is a trimmed copy of `game.js`'s loop (Kino's teleporter, reels and Easter eggs are left out; generic traps and teleporters come from markers: `updateTraps` and `updateTeleporters` in zombies.js, `buildTraps` and `buildTeleporters` in custom-world.js). Machine models face local +Z and markers face local +X, hence `FACE=π/2`.
- **Characters**: `characters.js` (registry `mods/characters/characters.json`; types `mannequin`, `gltf`, `t5`; `ThirdPersonCamera`). `mods/characters/mod.js` adds the character plus third person on T.
- **Settings**: `settings.js` (localStorage `kino.settings`: sensitivity, ADS sensitivity, invert Y, FOV, volume, render scale, FPS counter; `renderSettings()` builds the form). `game-menu.js` + `game-menu.css` add Settings and Main menu buttons plus a settings overlay to any game page's `#menu`, and apply volume, render scale and FPS; sensitivity and FOV are read directly in the loops. The main menu has a Settings tab.
- **Procedural rig** (`proceduralRig` in characters.js): a skinned glTF with no clips gets bones found by shape (legs = hips children going down, arms = `/arm/` chains, side from rest x, where +X is the character's left), then `aim()`s bones along character-space directions each frame. It covers idle, walk, run, a `hold()` aim pose and tail sway. For these rigs the held weapon is oriented in character space. Characters can carry a `credit` object (shown in the menu card, caption and Mods → Credits); repo-level attributions go in `CREDITS.md`.
- **Real FP arms** (`fp-arms.js`, `FirstPersonArms`; `characters.json` `fpArms: true`): clones the character, detaches its arm chains to a root in viewScene, and rebuilds each skinned mesh's index to keep only triangles more than 50% weighted to arm bones (no body collapse); the materials are toned by `fpArmsTone` (0.78). Each frame it poses them onto the active hidden T5 viewmodel (`api.view`, or the perk drink's `views[current]`): shoulder to elbow to wrist aim, the wrist pinned to `j_wrist`, palm basis (mid/index/pinky), and finger segments (`j_<finger>_<ri|le>_0..3`). Scale is set by palm length. That direction fit runs until the view's first `idle`, then `calibrate()` stores per-bone offsets (T5 world rotation to character world rotation), and later frames copy full rotations times the offset, which gives no twist flips. Arms stay visible while a new weapon loads. The game pages pass `view, viewScene, perkDrink` to mods; the menu Character tab's First person preview uses it too.
- **Keybinds**: `settings.binds` holds only the changed keys; `ACTIONS`/`DEFAULT_BINDS` are in settings.js. game-menu.js remaps in the capture phase: a rebound key is re-dispatched as the action's default `code`, and a default key whose action moved elsewhere is swallowed. The game loops are untouched.
- **Third-person held weapon**: the characters mod attaches the current weapon's `worldModel` to `character.hand` (mannequin right wrist, T5 `j_wrist_ri`, glTF regex or `handBone`), undoing the hand's scale; `entry.weapon` adjusts the grip. The mannequin has a two-handed aim pose via `hold()`.
- **First-person arms per character**: `characters.json` `hands` (`pow`/`usmc`/`pressure_suit` or a T5-rigged path) plus `handsTint`/`handsFlat`; `armsUrl`/`tintArms` in characters.js (tints the shared cached materials and keeps the originals). The characters mod swaps `data.characters.viewmodel_usa_pow_arms` in `prepare()`. The menu's Character tab has a Body / First person preview (a `ViewWeapon` holding the loadout primary).
- **Upstream files with local edits** (keep them small): `game.js` (mod hooks, render camera, settings sensitivity/FOV, `installGameMenu`), `audio.js` (`def.baseId??def.id`), `.tools/serve.mjs` (`KINO_HOME`).
- `.tools/make-sandbox-map.py` generates the Sandbox example map (uses every marker). Map thumbnails are in `mods/maps/thumbs/`.
- Full modding docs: `export/web/mods/README.md`.
