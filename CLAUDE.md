## Setup essentials

- Branch `custom` = local work. `upstream` = original repo (`git fetch upstream && git merge upstream/main && git lfs pull`). `origin` = backup fork github.com/darkmedic043/kino-der-toten; push `custom` there after committing.
- Pushing: `git push origin custom` is fine (needs `~/.local/bin` on PATH for git-lfs). The 2026-10-04 rule not to publish the Cheese Cube commit (`c4b3719`: WaW port tooling and the maps.json entry; the ripped map data was never in git) was lifted by the user on 2026-10-17 and the branch pushed.
- Served by the quadlet `kino.container` on **port 5190** (5173 is taken by deskpet) via `.tools/kino-server.mjs`, with the checkout mounted read-only. Edits show on a browser refresh; no restart needed. Public at https://zombies.terminallysleepy.com through the user tunnel `cloudflared-deskpet-memory` (leave the root `cloudflared.service` alone).
- Discord secrets are in `~/.config/kino/discord.env`. Never print or commit them. Player data is in `~/.local/share/kino`.
- git-lfs is at `~/.local/bin/git-lfs` (about 1 GB of assets). Host Node is 20 (`npm test` still passes); the container uses 24.
- No system browser. Use Playwright's Chromium in `~/.cache/ms-playwright`. The upstream `.tools/test-*.mjs` scripts hard-code Windows paths.
- **Whole-map test on a light copy (2026-11-13)**: `node .tools/map-lite.mjs <map-id>` once (16 px textures, simplified model, in `scratch/lite/`; rerun after a map rebuild), then `MAP=<id> PLAY=scratch/x.js flock scratch/melon/heavy.lock ~/.local/bin/lowpri node .tools/map-test.mjs` plays a real match on the whole map with a memory watchdog (Der Eisendrache: ready in about 58 s, renderer about 1.75 GB steady, a 2.0-2.5 GB peak for a few seconds while loading). For logic, collision, sounds and quests, not looks (performance.md).
- **Full-map headless runs break the memory rule (2026-11-09)**: Kino and Sandbox at Medium graphics with HD textures off pass 2.5-3.2 GB of renderer RSS before `ready` (load footprint, not per-step growth), so a look check of one asset goes in a `page.route`d test page with its own small scene and the same bloom + ACES (`scratch/glow/mini.mjs`: one gun about 270 MB; route the module under test to a scratch copy for before/after).
- Headless UI tests of a single module (e.g. MelonTerm's desktop.js): `page.route()` a fake same-origin `http://127.0.0.1:5190/test.html` (use 127.0.0.1, `localhost` doesn't connect), then `import('/mods/...')` in `page.evaluate` with stubbed opts. `playwright-core` only resolves from inside the repo (ESM ignores NODE_PATH): symlink `node_modules` into the scratchpad or run from the repo.
- Another session may have uncommitted edits in shared files (history.md, CLAUDE.md). To commit only your own line: `git show HEAD:<file> > tmp`, append your line, `git update-index --cacheinfo 100644,$(git hash-object -w tmp),<file>`, then commit; the working tree keeps everyone's edits. The index is shared too: a file staged and left there goes into whichever session commits next (2026-10-18, the Prismatic Punch / Dam-A-Nade work landed in the RADIO commit ce9df06), so stage and commit in one command, or build the commit from a temporary index (`GIT_INDEX_FILE=$tmp git read-tree HEAD`, add, commit). A commit from a temporary index leaves the shared index behind HEAD (its new files show as staged deletions, 2026-11-02): run `git reset -q -- <paths>` afterwards, or the next commit from the shared index deletes them.
- BO1 (base game) is installed via Steam; OpenAssetTools is built at `~/.local/opt/OpenAssetTools`. `.tools/build_wonder_weapons.py` builds extra wonder weapons from it into `mods/wonder-weapons/` (git-ignored assets; see `weapons.md`).
- Blender 5.2.2 (portable, `~/.local/bin/blender`) builds the terminal booth: `.tools/build-terminal-booth.py` (about 14 min per variant with the bake).
- KTX-Software 4.4.2 (official release, `~/.local/opt/ktx-software`, run with `LD_LIBRARY_PATH=lib`) encodes the KTX2 textures (`.tools/build-ktx2.mjs`).

## Rules that bite if forgotten

- **Visual checks go on the real GPU** (GTX 1660 Ti): `--use-angle=vulkan --enable-gpu --ignore-gpu-blocklist`. SwiftShader hides beam/bloom artefacts and draws points tiny. Check point sizes by maths.
- **Lighting**: never toggle a light's `.visible`, add or remove one mid-game, or keep one under a hidden group (the light count is in every lit program's key: everything recompiles; make lights at setup, drive intensity). Pool size is baked into shaders, so only resize it on a quality change. **Rebake** `baked-light.bin.gz` (`.tools/bake-lighting.mjs`) and `sunshafts.json` (`.tools/bake-sunshafts.mjs`) whenever fixtures or light sources change.
- Don't set `needsUpdate` on texture swaps (forces a program rebuild). Compile and upload during loading, not on the first played frame. Objects that only appear mid-game go in `host.warmObjects`, and late material changes belong in a `warm` handler, so the engine's `warmShaders()` builds them while loading (performance.md).
- Don't upload every weapon's HD textures up front (it fills VRAM). Preload only targeted ones.
- **Navmesh cache** (`custom-world.js`, 2026-10-29): a custom map's navmesh is kept in IndexedDB (`kino-navmesh`), keyed by its collision triangles, traversal links, cell size and headroom; changing the other `generateTiledNavMesh` settings needs `NAV_CACHE_VERSION` bumped or the old mesh keeps loading. Anything that appears mid-game must be in the warm-up (`host.warmObjects`, or hidden in `viewScene`) before `warmShaders` runs: a mod that loads models asynchronously must await them in its setup (Nuketown's zombies compiled at the first spawn: 2-3 s a program on D3D11). Mod setups over 250 ms print as `[mods] slow setups`.
- **Warm-up waits (2026-10-29)**: `warmShaders` runs after `pendingModels()` (every `loadModel` promise, animation.js) and `host.pending`; a mod must still await its own loads in setup (Der Eisendrache's zombies and gibs do now). Hitch entries in the perf log carry `tex n/KB/mip` (GL uploads in that frame) and `ev ...` (events of the 1.5 s before); `?texLog` records every upload with its caller in `kinoTexLog`. Per-map scripted matches: `MAP=<id> node scratch/perf2/map-match.mjs` (one page at a time on the GPU; explore-only maps hang it).
- **GPU-process trace (2026-10-29)**: the user's remaining D3D11 freezes happen with nothing from the page (0 programs/draws/uploads, `mt 0`, `lat` = the gap). On a Rind D3D11 session the engine asks Rind (0.8.2+) for a Chromium trace once per install (`localStorage.kinoTraceV`; `?trace[=s]` re-arms), uploaded to `~/.local/share/kino/traces/`; read it with `node .tools/trace-report.mjs latest` (performance.md). Hitch `ev` lists carry `hud:<id|class>` for HUD elements shown for the first time.
- **HUD paint warm-up (2026-10-30)**: the user's trace blamed the freezes on the driver compiling shaders at first use: Skia's for the HUD (each paint feature) and one WebGL program from the BO7 HUD's second renderer. `warmHud()` (engine.js) now paints every HUD element behind the loading screen and emits `warmHud(on)`: a mod whose HUD has a state that first shows mid-game (a class, a banner, an arc) must switch it on in a `warmHud` handler and restore it on `false`. `warmWeapons()` loads every weapon the match can hand out (wall buys, box, Pack-a-Punch, the loadout, ids mods add in a `warmWeapons(ids)` handler, each gun's Pack-a-Punched def too, every equipment def with a model) into the view scene before `warmShaders` and emits `warmWeapon({def,gun,wait})`: a mod that patches a viewmodel on equip must patch it there too (and `wait(promise)` for its own loads); the forced draw repeats the shadow pass, and the characters mod holds the loadout gun at load so third person compiles nothing. Measure with the draw recorder installed *before* the warm (`scratch/perf2/map-match3.mjs`); one installed at Ready reports the warm's draws as first draws (2026-11-01). Never create a second `WebGLRenderer` (its programs link on first use, unseen by the telemetry): draw into a render target on the game's renderer, at load. Host measurement: `scratch/perf2/map-trace.mjs` + `.tools/trace-report.mjs` (performance.md). **The freezes left after that were Skia's own shaders for the HUD's 2D paint** (2026-10-31: each new blur kernel, a text/box-shadow or drop-shadow at a new radius or scale, = a shader the NVIDIA D3D11 driver builds in 1-5 s, every session); Rind 0.8.3 rasterises the page's 2D content on the CPU (`--disable-gpu-rasterization --disable-accelerated-2d-canvas`), so HUD CSS can use blur freely there, but for browser players keep new HUD glows to radii already in use and don't animate the scale of a blurred element. A host trace lists them: `scratch/perf2/shader-list.py` (performance.md). For browser players `warmHud` also runs a paint sweep and edge probes over the HUD and the mods' warm states (`warmHud(on,wait)`: hud-bo7 ticks once and waits for its gun icon; classes, equipment paint theirs), 2026-11-01: a HUD state that first shows mid-game needs a warm state, or it compiles then. 8 Skia compiles remain in a browser (the BO7 panels' first raster as their own layers at the start, the announcement fade, a kill's blur); `scratch/perf2/skia-match.py` checks a trace against them. Every material answers `forceSinglePass=true` (engine.js) and `worldVariants()` precompiles held world-model materials: a new transparent double-sided material no longer costs two programs.
- **Mid-game texture uploads (2026-10-29)**: a texture an effect clones per use (fx sprites, the Thundergun streaks) must be `renderer.initTexture`d once loaded and never disposed, or three deletes the GPU copy with the last clone and re-uploads it (1-4 MB, a hitch) on the next effect; mod textures loaded with `TextureLoader` should push a promise on `host.pending`. The warm draw uses 1x1 stand-ins only for the view scene's hidden objects; hidden world objects (culled batches, props waiting to appear) upload their real textures at load. `MAP=<id> node scratch/perf2/map-tex.mjs` lists GPU texture allocations, uploads over 100 KB and re-uploaded textures after the start (performance.md). A `CanvasTexture` redrawn in play re-uploads the whole canvas with its mipmaps on every `needsUpdate` (the booth's CRT did 768 KB at 15 Hz): redraw only on a content change, animate with uniforms, or swap between pre-uploaded textures.
- **Viewmodel light**: on maps other than Kino/Moon the first-person lights follow the map's irradiance at the camera (`kino.vmLight`, lighting.md); a map that looks too bright or dark on the gun is tuned there (the gain curve), not by changing the scene lights.
- **KTX2**: textures under `textures/` are served as GPU-compressed copies from `export/web/ktx2/` (git-ignored). After adding or changing textures there, rerun `node .tools/build-ktx2.mjs` or the old copy keeps being served (materials.md).
- Colliders pushed onto `world.dynamic` need `.box` unless `window:true`, or `world.setDoors` crashes.
- Don't publish ripped or third-party game assets. The user supplies downloads: yt-dlp is blocked for me by the classifier, so give the user a command with the output template quoted (`-o "$HOME/Downloads/name.%(ext)s"`).
- **Mod order matters** (`mods/mods.json`): `weapon-levels` must load before `progression`, or the starting gun is built before attachments apply. 16 mods are **core systems** (`CORE_MODS` in `mod-loader.js`): always loaded even if dropped from mods.json; keep the two lists in the same order (core.md).
- **Profile saves**: `kino.mods.progression` is shared. Any code that saves a cached copy must take `weaponXp`/`attachments`/`camo`/`rewards` from storage first, or it wipes weapon XP, camo progress and map rewards (the Cheese Cube camo was lost this way, 2026-10-06).
- **Cloud saves** (2026-11-01): `setItem` on a tracked key stamps the copy as newest. Code that runs before the sync must use `rawSet`, or an old device overwrites the account (setup.md). Copies of every save are in `~/.local/share/kino/profiles/<id>.history/`.
- **Attachments**: BO1 viewmodels carry every attachment, hidden by `hideTags`. Read availability from the *pristine* `hideTags` (applying attachments un-hides tags). Viewmodels are cached, so re-show bones on equip. Surfaces share one vertex buffer, so iterate a mesh's **index**, and treat a mesh as hidden when its dominant bone chain is scaled ~0. Some Pack-a-Punched guns show extra parts natively (the Commando's dual mag, the PM63's extended mag): compare against the stock base/upgrade `hideTags` before treating a part as attachment-added.
- Materials are shared between copies of a model: per-mesh changes (hiding dot cards) must not be skipped by a per-material "already patched" check, and temporary material changes (Gunsmith pulse) must be restored.
- **Rind installs** (`.tools/install-manifest.mjs`, `GET /api/install/melon-zombies`): only redistributable files are installed on players' PCs; code is picked up automatically, but new *own* data or assets (not from BO1/BO3 or other third parties) need a rule in its `OWN` list, and anything ripped or third-party must never match it.
- **Der Eisendrache placed props** (`mods/der-eisendrache/merge-props.js`): pieces of repeated props and window boards are drawn as InstancedMeshes; the original meshes stay in place on no render layer (`layers.mask = 0`) and the instances copy their nodes' matrices and visibility each frame. Move or show a placed prop through its node (position, `visible`), never by editing its meshes' materials or visibility (since 2026-11-13 single pieces and door parts are followers in the engine's texture-array batches, `userData.batchFollow`: the mesh stays in place on no render layer, and editing its material sends it back to drawing itself, performance.md), and call `updateMatrixWorld(true)` after moving it (the map root doesn't auto-update). The map's version query (`maps.json` `?v=`) must be bumped on every rebuild; build with `--tex 512 --prop-tex 256` or the textures are regenerated. After a rebuild run `.tools/castle-after-rebuild.sh` (the void-ceiling table that draws the black planes overhead as stone, then the light volume, map detail, light copy and gz; `node .tools/castle-ceilings.mjs status` tells whether the table fits the GLB; waw-ports.md).
- **Static freeze (whole scene, 2026-10-17)**: every object in the scene is frozen at load (`static-freeze.js`), all-static subtrees are skipped by three's matrix walk, and the scene root no longer composes its matrix. A node a mod moves thaws within two frames; `updateMatrix()` then `updateMatrixWorld(true)` after a move makes it immediate. Exception: a custom map's own nodes come out of `optimizeStaticScene` with `matrixAutoUpdate` already off, and the freeze never thaws those: under `world.root` call `updateMatrix()` yourself, or turn `matrixAutoUpdate` back on at the mod's setup as Der Eisendrache does for its CASTLE_ subtrees (2026-10-22). Bones with nothing attached are `visible = false` (`hideBones`): attach things to bones with `bone.add`/`attach` (the chain re-shows itself), never by re-parenting around it.
- **Der Eisendrache instanced pieces leave the scene graph** (merge-props.js, 2026-10-17): a mod that needs a placed prop's meshes by traversal after the mod's setup (the gondola gates' colliders) must have its node prefix in merge-props `SKIP`; moving or showing a node still works (instances follow their parent node).
- **Player collision caches nearby triangles** (collision-world.js): after editing the collision geometry at runtime, call `world.collision.invalidateCache()` (the booths do after clearing debris); `useCache = false` gives the plain BVH walk for A/B tests.
- **Static batches and mod nodes (2026-11-18)**: every plain mesh under `world.root` joins a static texture-array batch at load and leaves the scene graph (`instance-cull.js`). A node a mod adds under `world.root` that later moves or hides needs `userData.noMerge` (or `batchFollow` on its meshes, as Der Eisendrache's gondola cars), or the batch draws it at its load position forever (the undercroft power gate stayed drawn shut). `kino.debug.step()` doesn't run the render path where followers sync: wait real frames in a test (custom-maps.md, performance.md).
- **Culling (2026-11-17)**: the instance culler view-culls a shadow-casting batch only after `kino.instanceCull.cullShadowCasters(true)`: a map that tags its meshes `castShadow` must call it and draw its own shadow maps between `restore()` and `reapply()` (Gorod Krovi's `sun.js`), or every prop in range is drawn whichever way the camera faces (2,400 draw calls / 20 M triangles there). Rigged models load with `frustumCulled = false`: a placed rigged prop that mostly rests goes through `autoCull(root)` (`mods/gorod-krovi/scene-props.js`), or it is drawn every frame from anywhere and again in every shadow pass. Per-pass triangle and draw tally: `.tools/pass-tally.mjs` (performance.md).
- **Visibility culler (2026-11-17, `vis-cull.js`, engine)**: loose props that rest are grouped at load and hidden while a GPU occlusion query finds their box behind walls (`userData.occluded`, honoured only in the main world draw: hidden props still cast shadows). A mod that moves a prop needs nothing (a moved group wakes itself); `kino.visCull.add(root)` registers props added after load, `wake(node)` forces a redraw now, `exclude(node)` or `userData.noVisCull` opts out. `?noVisCull` / `kino.visCull.enabled=false` for an A/B; `stats().flips` must not grow under a still camera (performance.md). Gorod Krovi's sun draws the resting groups' shadows once into its static map and leaves them out of its per-frame pass (`userData.shadowBaked`, 2026-11-18): a prop changed some other way than by moving a node or a mesh's `.visible` needs `kino.visCull.wake(node)`, or its old shadow stays; `kino.gkSun.bake=false` for an A/B.
- **Zombies cost only what is in view (2026-11-21, `rig-lod.js`, `kino.rigLod`)**: the engine writes each enemy's bounds into its skinned meshes every frame and frustum-culls them; an off-screen enemy animates at 30 Hz and its matrix walk runs once a frame. Don't set `frustumCulled` or `boundingSphere` on an enemy's meshes; a mod that needs an enemy's bones fresh every frame while off screen sets `z.noRigLod = true`. Skinned meshes of one actor share a `Skeleton` (`shareSkeletons`, still-skeletons.js): never count on one per mesh. A/B switches: `?noRigLod`, `?noShare`, `?batchUploads` (three's per-call batch index upload, guarded in instance-cull.js), `?slowUniforms` (stock uniform setters, `uniform-fast.js`). Where garbage comes from: `HEAP=out.heapprofile` on `.tools/map-test.mjs`, then `node .tools/heap-summary.mjs` (performance.md, last section).
- **Real light shafts (2026-11-17, `mods/lighting/shafts.js`)**: a map's shadow-casting sun gets ray-marched shafts with `kino.shafts?.add(light,{strength,lift,sky,indoor,white})` (High/Ultra; drawn in the volumetric pass from the light's own PCF shadow map, so only what is in that map cuts them). Strengths are tiny (Kino .045, Gorod .012); Kino's baked sun cones step aside while they draw. Tune live in `kino.shafts.lights` (lighting.md). A map whose key light casts no shadows gets its rays from one depth draw at load instead: a line in `MAPS` of `mods/lighting/sun-shafts.js` (2026-11-19; `kino.sunShafts`, `?noSunShafts`; keep `strength` low, `indoor` carries the rays; the static batches it draws are children of the scene, not of `world.root`).
- **Post chain (2026-10-22)**: `mods.renderWorld(scene,cam,{viewScene,viewCamera,drawView})` returns true when the lighting mod drew the viewmodel inside its composer (after AO, before bloom and the grade); the engine then skips its own draw. The grade pass replaces OutputPass (tone mapping + sRGB live there now); per-map looks in `GRADES` (`mods/lighting/grade.js`) or a map entry's `grade`; tune live with `kino.post.set({...})`. Settings `filmLook`/`filmGrain`. Low graphics has no composer, so no grade. The haze pass also applies the fires' heat shimmer (`kino.heatScene` drawn to `heatRT`, read as `tHeat`; lighting.md Fire).
