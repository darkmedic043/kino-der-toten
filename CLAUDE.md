# Kino der Toten (local modding fork)

The user's fork of luckeyfaraday/kino-der-toten, a Three.js browser
reconstruction of Black Ops Zombies. The upstream developer guide is
`AGENTS.md`. Read it for the upstream layout and test commands.

## Fork setup

- Branch `custom` holds local work. The `upstream` remote is the original repo; update with `git fetch upstream && git merge upstream/main && git lfs pull`. The `origin` remote is the user's backup fork https://github.com/darkmedic043/kino-der-toten (public, because forks of public repos must be; default branch `custom`). Push `custom` there after committing. LFS objects are shared with the upstream fork network, so pushes upload only new LFS files.
- **Public URL**: https://zombies.terminallysleepy.com, through the user's own locally managed Cloudflare tunnel `deskpet-memory` (`~/.cloudflared/config.yml`, user service `cloudflared-deskpet-memory.service`; the ingress was added before the 404 catch-all, and the pre-change backup is `config.yml.bak-kino`). The root `cloudflared.service` runs a different, dashboard-managed tunnel; leave it alone.
- **Accounts**: `.tools/kino-server.mjs` replaced `serve.mjs` in the quadlet. It serves static files plus `/api/{config,me,auth/discord,auth/discord/callback,auth/logout,profile}`. Discord OAuth2 uses the code flow with scope `identify`: a one-time `state` cookie (`kino_oauth`, path `/api/auth`, 10 min), the code is exchanged server-side, and `/users/@me` supplies the name and avatar; the session sub is `discord:<id>`. Sessions are an HttpOnly cookie (90 days, `Secure` behind https). Data lives in `~/.local/share/kino` (bound to `/data`: `sessions.json`, `profiles/<sha256(sub)>.json`). Cross-origin non-GET requests are refused. Credentials `DISCORD_CLIENT_ID`/`DISCORD_CLIENT_SECRET` are in `~/.config/kino/discord.env` (mode 600, outside git, loaded via the quadlet `EnvironmentFile`); `KINO_PUBLIC_URL` is set in the quadlet, and the redirect is `<public>/api/auth/discord/callback`, registered in the Discord developer portal. Never print or commit the secret. Caching: the zone's Browser Cache TTL rewrites `no-cache` to `max-age=14400`, so the server sends `no-store` for html/js/css/json/md/txt (Cloudflare passes it through as BYPASS/DYNAMIC) and `public, max-age=86400` for heavy assets. Client side: `cloud.js` patches `localStorage.setItem` for `kino.mods.progression|settings|best*`, stamps `kino.cloud.updatedAt`, pushes after 2 s or on pagehide, and on load syncs newest-wins; `cloudReady` is awaited by home.js and the progression and characters mods. Sign-in only happens on the public origin; other origins show a link to it.
- Served by the Podman quadlet `~/.config/containers/systemd/kino.container` (image `node:24-alpine`, checkout bind-mounted read-only at `/app`, running `.tools/kino-server.mjs 5190`) on **port 5190**. Port 5173, the upstream default, is used by the deskpet electron-vite dev server on this host. The server sends `Cache-Control: no-cache`, so file edits show up on a browser refresh without a restart.
- Git LFS is installed as a user binary at `~/.local/bin/git-lfs` (no system package). The LFS assets are about 1 GB.
- Host Node is 20 and upstream wants 24. `npm test` passes on 20 anyway. The container uses 24.
- No system browser is installed. Browser checks use Playwright's headless Chromium in `~/.cache/ms-playwright` with `--use-angle=swiftshader --enable-unsafe-swiftshader`. The upstream `.tools/test-*.mjs` scripts hard-code Windows Chrome paths, so they won't run as-is. Software WebGL is slow: hide the canvas before UI screenshots, and don't render Kino and another map in one browser at the same time.

## Fork-only architecture

- **Main menu** `export/web/home.{html,css,js}` is served at `/` via `KINO_HOME=home.html` (env var read by `.tools/serve.mjs`, set in the quadlet). Kino itself is `/index.html`. Tabs: Play (map browser from `mods/maps.json`), Loadout (weapon thumbnails rendered from world models, stats, bonuses), Character (3D preview), Mods. `maps.html` just redirects to `./#play`.
- **Profile** `profile.js`: shared localStorage profile (`kino.mods.progression`: xp, level, loadout, character, stats), plus unlock rules read from `mods/progression/progression.json`. The menu and the progression mod both use it.
- **Mod loader** `mod-loader.js`: `ModHost` merges data patches (objects merge, arrays replace, `null` deletes, `{add,remove}`, weapon `"extends"` which also sets `baseId`), calls an optional `prepare(data)` from scripts, wraps session/enemies methods to emit events, then runs `setup(api)`. `host.camera` and `host.hideViewmodel` let a mod take over rendering.
- **Custom zombies maps**: `custom-world.js` (the `CustomWorld` class) builds a world from a glTF plus named markers (`PLAYER_SPAWN, ZSPAWN, WINDOW, DOOR, WALLBUY, PERK, BOX, PAP, POWER, CLAYMORE, TRAP, TRAPZONE, TELEPORT, TPDEST, EGG`); glTF lights are scaled by scale² for the inch units and `POWERLIGHT_*` lights follow the power; dog rounds fade in fog; unusable markers go to `world.warnings`, which is shown on the map's start menu. It exposes the same interface as upstream `world.js`, so upstream `Enemies`, `MysteryBox` (fed stand-in `data.entities`), `Powerups`, `PerkDrink` and `KinoFeatures` run unchanged. The navmesh is generated in the browser with `vendor/recast-generators.mjs` (a copy of `@recast-navigation/generators` 0.43.1 in the importmap), tiled so door blocking (poly flags) stays local. `zombies.{html,js,css}` is a trimmed copy of `game.js`'s loop (Kino's teleporter, reels and Easter eggs are left out; generic traps and teleporters come from markers: `updateTraps` and `updateTeleporters` in zombies.js, `buildTraps` and `buildTeleporters` in custom-world.js). Machine models face local +Z and markers face local +X, hence `FACE=π/2`.
- **Characters**: `characters.js` (registry `mods/characters/characters.json`; types `mannequin`, `gltf`, `t5`; `ThirdPersonCamera`). `mods/characters/mod.js` adds the character plus third person on T.
- **Settings**: `settings.js` (localStorage `kino.settings`: sensitivity, ADS sensitivity, invert Y, FOV, volume, render scale, FPS counter; `renderSettings()` builds the form). `game-menu.js` + `game-menu.css` add Settings and Main menu buttons plus a settings overlay to any game page's `#menu`, and apply volume, render scale and FPS; sensitivity and FOV are read directly in the loops. The main menu has a Settings tab.
- **Motion model** (`motionModel()` in characters.js, shared by the procedural rig and the mannequin): `update(dt, speed, {forward, side, vy, grounded, turn})` gives a stride phase (reversed when backpedalling), run blend, strafe heading (legs swing along the movement), air/land impulses and turn lean. The pose layers are pelvis bob/sway/twist, torso counter-twist, breathing, idle head glances, knee/foot roll, arm pump, jump tuck, landing crouch and tail. The characters mod computes these from the feet delta, camera yaw rate and `player.state.grounded`.
- **Procedural rig** (`proceduralRig` in characters.js): a skinned glTF with no clips gets bones found by shape (legs = hips children going down, arms = `/arm/` chains, side from rest x, where +X is the character's left), then `aim()`s bones along character-space directions each frame. It covers idle, walk, run, a `hold()` aim pose and tail sway. For these rigs the held weapon is oriented in character space. Characters can carry a `credit` object (shown in the menu card, caption and Mods → Credits); repo-level attributions go in `CREDITS.md`.
- **Real FP arms** (`fp-arms.js`, `FirstPersonArms`; `characters.json` `fpArms: true`): a one-time rebind onto the T5 viewmodel skeleton. It clones a T5 hands model at its bind pose (`skeleton.pose()`), poses the character's arm, hand and finger bones over it (palm-length scale, direction aims, palm basis, finger chains), slides each arm so the wrists meet, then bakes the arm-weighted triangles (forearm down unless `fpArmsUpper`) into T5 bind space (`bindMatrix⁻¹`) with weights remapped to `j_shoulder/elbow/wrist/<finger>_<ri|le>_<n>`. `attach(hands)` adds a SkinnedMesh bound to each weapon rig's own skeleton and hides the T5 arms, so all animations (reload, knife, perk bottles) deform it natively. Options: `fpArmsScale`, `fpArmsTone`. The game pages pass `view, viewScene, perkDrink` to mods; the menu preview uses it too.
- **Lighting mod** (`mods/lighting`, rewritten 2026-09-29). Kino: the 36 exported `light` entities plus fixture script_models become sources; high narrow spots (fov ≤ 60, y > 400) become spot sources (theatre balcony spots aim at the stage ≈ (0,90,−1100); the export lost their targets; lobby ones aim down). The theatre chandelier (radius 1700, drop 120) and `lights_hang_single` are downward spot fixtures. A pool of 12 PointLights follows the strongest sources; up to 4 shadow-casting SpotLights (High 2 at 1024², Ultra 4 at 2048²) follow the nearest spot sources. `renderer.shadowMap.autoUpdate=false` with refresh at 30/60 Hz; never toggle light `.visible` (recompiles every shader); `castShadow` changes only with quality. Exposure 1.45, fill scaled to ambient .19 / hemi .21 / dir .12, darker fog and background. Spot sources get additive fresnel beam cones (ShaderMaterial) and drifting dust Points. With the power on, the chandelier materials get an emissive map of the candle-bulb block (top-left 20/128 of the texture). All maps: `host.renderWorld` runs an EffectComposer (4× MSAA HalfFloat target): RenderPass → GTAOPass (High+) → UnrealBloomPass (.38, .55, .82) → OutputPass. Settings → Graphics quality (`settings.graphics` 0–3, default 2; touch devices cap at 1). The add-ons are vendored from node_modules/three 0.185.1 into `vendor/jsm/{postprocessing,shaders,math}`.
- **Music**: the `settings.music` toggle (default off); game-menu.js wraps `audio.playMusic` so 'ambience' only plays when it's on (Easter-egg songs unaffected).
- **Third-person crosshair**: `ThirdPersonCamera` looks at the point where the eye camera's forward ray hits the world (min 60, max 3000), so the screen centre matches where shots land (verified within about 1 px).
- **Player health mod** (`mods/player-health`): `rules.player_health` 150 and `player_health_juggernog` 250 in its data.json. It overrides the `session.maxHealth` getter and refills on `reset` and after a Quick Revive (the game hardcodes 100). A zombie hit does 50, so 3 hits; dogs 40, novas 45.
- **Combat feedback mod** (`mods/hud`): synthesized WebAudio thumps (a sine pitch-drop punch plus a low-passed noise knock) for hits (higher for headshots, a second deeper thud on kills) and a heavier two-layer thump when hurt, through their own gain-2.4 bus and a compressor into `audio.master` (the game has no flesh or pain cues). The directional damage indicator is `#damage-ring` arcs; the attacker is inferred as the nearest enemy with `state==='attack'&&attackDealt` within 140 (the game doesn't pass it), and the arc is rotated by atan2(right, forward) each frame for 1.6 s.
- **HUD portrait**: `renderPortrait(entry,data)` in characters.js renders the character once to a 160 px PNG (head bone or top of the bounding box, 3/4 view, `portraitSpan` 0.15 × height). The characters mod shows it as `#hud-portrait` above the round panel, with a red flash when hit.
- **Co-op** (`mods/multiplayer`, `net.js`, server rooms): the server has a dependency-free RFC6455 WebSocket at `/api/ws` (upgrade handler, masked client frames, 25 s pings) and rooms of 4-letter codes, max 4, where the creator is host and the room closes when the host leaves; `GET /api/rooms/<code>` returns `{page, map, players}` for join-by-code. Relay protocol: `{t:'to',target:'host'|'all'|id,data}` becomes `{t:'msg',from,data}`. Game protocol: `pose` (all, 15 Hz), `snap` (host, 12 Hz: round, phase, doors, power, boards, zombies `[id,kind,x,y,z,yaw,state,hp,speed]`, and a `gid` that changes on host reset), `dmg` (client→host) answered by `res` (points/XP applied on the client), `hit` (host→victim), `world` (client doors/power), `ended`. The host sets `enemies.targetFor` (nearest player, sticky ×1.3) and wraps `enemies.onDamage(amount,z,victim)`; the `enemies.js` upstream edit adds the `targetFor` hook plus `victim` args. Clients replace `enemies.update`/`hurt`/`nuke` with a mirror. `host.remoteDamage` suppresses host XP and hitmarkers for teammates' hits (`kill` event `remote` flag). URL: `?mp=host` creates, `?room=CODE` joins (history rewrites to `?room=`). Stage 3: power-ups are host-authoritative (host ids `nid`, the snap `pu` list, `pu` collect broadcast calls `kino.debug.collectPowerup` everywhere, and the host also grabs for remotes within 70); the box location is in the snap `box` (client teddy moves are sent as `box`); custom-trap activations are broadcast as `trap`; Kino trap kills already propagate through `dmg`. Stage 4: in co-op, a lethal hit without QR is intercepted (`session.damage` wrapper) and becomes DOWN (phase `reviving`, reviveLeft ∞, perks cleared, 30 s bleed-out, camera lowered and rolled); teammates hold F (tracked via KeyF/KeyE) within 90 for 3 s and send `revive`; bled-out players are DEAD and spectate via `host.camera`, respawning on `roundEnd`; everyone down gives the host `gameover` broadcast and `forceGameOver()`. The snap phase maps the host's personal `reviving` to `fighting`. Host migration: the server reassigns the host on leave (`left` carries `host`) and the new host calls `becomeHost(true)` (restores the original enemies/powerups functions; mirrored zombies keep their host ids because clients set `z.id=netId`). A Worker-driven 20 Hz ticker keeps the host simulating while paused or hidden. The HUD label switches from SOLO to CO-OP.
- **Movement mod** (`mods/movement`): gravity 1400 (jumpSpeed recomputed for jumpHeight 39); groundAcceleration 1500, except the game's original 2600 on stairs (`state.stairs` is set for 0.35 s whenever `onFloor` flips without a jump); airAcceleration 320 only after a real jump (detected from the jump key) or 0.2 s airborne. It wraps `player.update(dt,input)`: stair snap-down (a ray ≤ stepHeight+4 after walking off an edge), a **one-button crouch** (C/Ctrl, tracked by its own key listeners in game time: tap toggles crouch, holding 0.35 s goes prone, a tap while sprinting at >220 slides; jump from crouch or prone stands; sprint cancels a toggled crouch; `input.crouch` is overridden). **Prone** swaps `crouchHeight` 30, `crouchEyeHeight` 17 and `crouchSpeed` 45 (stands only if `_canUseHeight`). **Slide** lasts 1.35 s with speed = 130 + (start−130)·(1−u)^1.7, start = min(490, h·1.6), applied after the controller step along a slowly steering dir; it ends early on a wall hit, emits a `slide` event, and plays the data.json `slideSound` file or a synthesized band-passed noise scrape, **mantle** (jump near a wall whose top is 19–74 above the feet with room to stand, checked by a ray pair plus `capsuleIntersect`: a scripted 0.28 s + rise/260 climb). Camera: head bob, landing dip only on real falls (>0.22 s airborne and vy<−260), strafe/slide/mantle roll, eased eye-height changes. The state is exposed as `kino.movement.state`. `applyStance()` in characters.js pitches the character root (prone +1.45 face-down, slide −0.85, mantle +0.35; YXZ order) and `setStance` turns the aim pose past the head when prone; co-op poses carry `k` (stance). The motionModel landing threshold is −300 (no crouch per stair).
- **Moon wonder weapons mod** (`mods/moon-weapons`): `prepare()` copies `microwavegundw_zm`, `microwavegun_zm` and `minigun_zm` from `moon/combat-data.json` (asset paths are already web-root relative) with projectileSpeed and explosionRadius set to 0 (hit-scan), and adds the Wave Gun and Death Machine to `boxPool`. `setup()` merges the Moon `wpn/microwave` and `lmg/minigun` audio cues, wraps `audio.weapon`, makes Zap Gun bullet hits lethal via `beforeEnemyDamage`, runs the Wave Gun cone kill (range 1000/1400, dot > 0.78) when `session.shots` increments, and B swaps dw ↔ combined (separate ammo stored on `weapon.other`; the first swap gives the other form the same share of its ammo, and a wrapped `session.powerup('full_ammo')` refills the stashed form too).
- **Zombie voices mod** (`mods/zombie-sounds`): reads `sounds.json` {growl, attack, death: [files]} next to its clips. It replaces `enemies.onSound('growl')`, plays attack on a state change to attack and death on `kill`, with distance falloff to 1400 and random pitch. `.tools/split-sounds.py <audio> <folder>` cuts a compilation at silences (ffmpeg silencedetect), loudness-normalises it to ogg, and writes clips.json and a first-guess sounds.json. Until clips exist it logs one 404 and keeps the synthesized growl. YouTube downloads via yt-dlp were denied by the permission classifier, so the user fetches the audio themselves.
- **Thundergun mod** (`mods/thundergun`): the exported Thundergun glTFs lost their alpha modes, so the mod patches the shared cached materials once (loaded via `loadModel`, so the viewmodel, box display and third-person hold are all fixed): alphaTest 0.5 only on the wire mesh (the body texture's alpha is not a cut-out mask: cutting it removed the dashed ammo ring and ribbed strips); `chamber_glass` and the lens become transparent; `chamber_main` becomes an additive, emissive, scrolling energy texture that flares on each shot. It wraps `audio.weapon` ('shot' + base id `thundergun_zm`) to spawn a shockwave in the world scene (streaked additive cone, three expanding rings, muzzle flash sprite, dust points, and a screen flash overlay) sized to the game's 600-unit, dot > 0.65 kill cone. It tags `cause==='thunder'` victims in `beforeEnemyDamage` and throws their corpses on `kill` (ballistic arc, wall and ground raycasts, backward tilt); skipped for `host.remoteDamage`.
- **Cheat console** (`mods/cheats`): ` (Backquote) or the pause menu's CONSOLE button opens a text console (it pauses the game, and on close recaptures the pointer). Commands: help, weapons [filter], give/spawn <weapon> (partial names; Tab completes), pap, points, god, ammo, perk <jug|speed|doubletap|quick|all>, round <n>, killall, powerup <type>, heal, clear. The first cheat command sets `window.kino.cheats.used` until the next `reset` (new game), and shows a CHEATS · NO XP badge. The progression mod's `cheating()` then blocks XP, kills, best round and the results line; game.js and zombies.js skip the `kino.best*` write. Cheats are refused in co-op rooms (`kino.coop.code`). The console input stops key propagation, and game-menu.js's rebind remap ignores keys typed in text fields.
- **Weapon-part animation fix** (upstream `animation.js` edit): T5 viewmodel xanim *translations* on weapon-model bones (bolts, magazines, pumps, straps, the Thundergun's `tag_pump` → rig → `tag_clip` drum, the Zap Gun/Wave Gun parts) are displacements from the bone's bind position, while rotations are absolute. `makeClip` used to apply them as absolute, which pulled parts into the receiver: the Thundergun's drum (its magazine) vanished into the body and its barrel floated detached, the reload barely moved, and the MP40 magazine sat about 4 units off. `ViewWeapon.equip` now stores `userData.bindPosition` on every gun and left-gun bone except `j_gun`/`j_gun1` (anchors, or animated perk bottles), and `makeClip` adds it to position keys. Hands and locomotion clips are unchanged. Evidence: 1,848 gun position tracks look like pure single-axis offsets (e.g. M1911 empty slide −2.16,0,0; Ithaca pump 4.06,0,0); rotation tracks mostly match the bind pose (absolute).
- **Thundergun ammo bulbs** (`mods/ammo-counters`): the original showed rounds in the magazine as red lights on the drum (FX on `tag_bulb1-8`, not exported). The mod wraps `view.equip`, adds an additive red sprite to each `tag_bulb` bone of the Thundergun viewmodel, pushes each sprite 0.9 out along the gun’s −X (the tags sit 0.15 behind the drum face, so the glow was buried), and lights bulb n while `mag ≥ n` (2 normally; Pack-a-Punch 4, but the model has no `tag_bulb4`, so 3 show, as in the original). The Zap Gun's "87" is a printed decal in the original, not a counter.
- **Kino map materials** (`mods/map-materials`, Kino only): normal maps: the export attached none, but 400+ ship in `textures/` in DXT5nm layout (X in alpha, Y in green). `.tools/build-kino-normals.py` converts the matched ones to standard RGB normal maps in `textures/nrm/*.webp` (236 files, 7.6 MB) and writes `normals.json` (material name → map); the mod loads them after start with normalScale (1, −1) and max anisotropy on colour maps. The theatre chandelier's opaque slot also holds bead and crystal cards, so an `onBeforeCompile` discard cuts alpha < .45 only where fract(uv.x) < .49 (the frame half has zero alpha too). the map export lost blend modes. Glass (`global_glass*`, `dec_glass01`, lightning chamber glass, plus model glass like `mtl_glass_v2_off`) was a 0.45 alpha cut-out, so clear panes vanished and frosted ones went solid; it is now alpha-blended with depthWrite off. Dark-on-white stains (burntstain, darkstain, grime, scorch, pipe stain, blast crater) use MultiplyBlending with polygon offset; soft decals (blood, cracks, puddles, `*_blend`) blend instead of cutting at 0.45. `hdrportal_lighten` (an editor light portal) is hidden and `clothcable_glow` is additive. Layered `base:decal` materials (names containing ':') are left alone. It also caps the spawn-room return teleporter pad (centre 2,1274; its collision is a bowl from rim ~89–92 down to ~78) with an invisible 57-radius cylinder collider (top 89.4) pushed onto `world.dynamic`.
- **Stairs** (upstream `player-controller.js` edit): a riser collision projected the walking speed away and `_tryStep` never restored it. Steps are now also tried when the last contact is a non-floor surface facing against the movement (dot < −0.3; an edge brushed while descending faces along it and is ignored), and a successful step restores the pre-collision horizontal velocity. Measured with a navmesh stair walker: Kino's real staircases climb 10–55% faster with 0–14 slow frames instead of up to 177; descents are unchanged.
- **Stair camera smoothing** (movement mod): grounded feet jumps of 1.5 to stepHeight+6 in one frame (step-ups and snap-downs) go into `stairOffset`, which the camera absorbs and eases out (rate 11/s, clamp ±24); bigger jumps reset it. Camera jerk on the big lobby-side staircase went from max 4.3 (21 frames > 1.5) to 1.5 (1 frame).
- **Third-person action layer** (characters.js `motionModel` + `actionPose`; mannequin and procedural rigs): sprung impulses `act('recoil'|'slap'|'flinch',amount,{x,z})` and eased envelopes and phases via `pose({reload,drink,swap,sprint,ads,melee,throw})`. The characters mod drives them: recoil kick per weapon (fireTime, pellets; Thundergun 2.2), reload envelope with a slap at 60%, knife phase from `meleeLeft`, grenade count drop → 0.55 s throw, weapon swap dip, drink, sprint carry, ADS, and a flinch away from the nearest zombie on `beforeDamage`.
- **Slides on slopes** (movement mod): a slide starts if grounded or airborne < 0.25 s (slopes flicker), when sprinting above 170 (was 220; uphill is slower), and the start speed is at least 220 × 1.6. While sliding, the player is snapped to the ground below (reach stepHeight + speed·dt·1.5); the ground normal's horizontal part gives a downhill boost (gravity × 0.9, clamped −start to +420) and slows the slide timer downhill; the slide ends if stalled below 0.6 × endSpeed.
- **Zap Gun ↔ Wave Gun transitions** (moon-weapons mod): the Zap Gun rig's `altDropAnim` (dw_2_combo, 1.73 s, with `wpn_micro_rld_join`) plays before swapping to the Wave Gun; splitting equips the Zap Guns and plays `altRaiseAnim` (combo_2_dw, 1.33 s, with `wpn_micro_rld_separate`). `equipInPlace` skips the normal raise, firing is locked via `session.fireLeft`, and the other form's model and animations are preloaded while either is held.
- **Thundergun reload sounds** (thundergun mod): `notetrackSounds` maps `sndnt#fly_thundergun_cell_lock` to `fly_thundergun_cell_slide_lock`, and the mod plays `fly_thundergun_eject` at 6% and the charging beep `fly_thundergun_cell_on` at 76% of the reload (both have no animation cue).
- **Mystery box performance** (upstream `mystery-box.js` edit): each weapon's centred display copy is cloned once (`display(id)`, cached in `this.displays`) and reused, instead of a SkeletonUtils clone and dispose on every spin swap (about 30 ms each, up to 20 per second). `warm(renderer,camera)` compiles shaders and uploads every box weapon's textures during loading; game.js and zombies.js call it after `mods.start`, desktop only (skipped on mobile for memory).
- **Keybinds**: `settings.binds` holds only the changed keys; `ACTIONS`/`DEFAULT_BINDS` are in settings.js. game-menu.js remaps in the capture phase: a rebound key is re-dispatched as the action's default `code`, and a default key whose action moved elsewhere is swallowed. The game loops are untouched.
- **Third-person held weapon**: the characters mod attaches the current weapon's `worldModel` to `character.hand` (mannequin right wrist, T5 `j_wrist_ri`, glTF regex or `handBone`), undoing the hand's scale; `entry.weapon` adjusts the grip. The mannequin has a two-handed aim pose via `hold()`.
- **First-person arms per character**: `characters.json` `hands` (`pow`/`usmc`/`pressure_suit` or a T5-rigged path) plus `handsTint`/`handsFlat`; `armsUrl`/`tintArms` in characters.js (tints the shared cached materials and keeps the originals). The characters mod swaps `data.characters.viewmodel_usa_pow_arms` in `prepare()`. The menu's Character tab has a Body / First person preview (a `ViewWeapon` holding the loadout primary).
- **Upstream files with local edits** (keep them small): `enemies.js` (co-op `targetFor` hook), `mystery-box.js` (display cache and warm-up), `animation.js` (weapon-part position tracks relative to bind), `player-controller.js` (step-up keeps speed), `settings.js` (graphics quality), `game.js`/`zombies.js` (`renderer` in the mod api and the `mods.renderWorld` hook), `game.js` (mod hooks, render camera, settings sensitivity/FOV, `installGameMenu`, box warm-up, cheat check on best round), `audio.js` (`def.baseId??def.id`), `.tools/serve.mjs` (`KINO_HOME`).
- `.tools/make-sandbox-map.py` generates the Sandbox example map (uses every marker). Map thumbnails are in `mods/maps/thumbs/`.
- Full modding docs: `export/web/mods/README.md`.
