## Setup essentials

- Branch `custom` = local work. `upstream` = original repo (`git fetch upstream && git merge upstream/main && git lfs pull`). `origin` = backup fork github.com/darkmedic043/kino-der-toten; push `custom` there after committing.
- Pushing: `git push origin custom` is fine (needs `~/.local/bin` on PATH for git-lfs). The 2026-10-04 rule not to publish the Cheese Cube commit (`c4b3719`: WaW port tooling and the maps.json entry; the ripped map data was never in git) was lifted by the user on 2026-10-17 and the branch pushed.
- Served by the quadlet `kino.container` on **port 5190** (5173 is taken by deskpet) via `.tools/kino-server.mjs`, with the checkout mounted read-only. Edits show on a browser refresh; no restart needed. Public at https://zombies.terminallysleepy.com through the user tunnel `cloudflared-deskpet-memory` (leave the root `cloudflared.service` alone).
- Discord secrets are in `~/.config/kino/discord.env`. Never print or commit them. Player data is in `~/.local/share/kino`.
- git-lfs is at `~/.local/bin/git-lfs` (about 1 GB of assets). Host Node is 20 (`npm test` still passes); the container uses 24.
- No system browser. Use Playwright's Chromium in `~/.cache/ms-playwright`. The upstream `.tools/test-*.mjs` scripts hard-code Windows paths.
- Headless UI tests of a single module (e.g. MelonTerm's desktop.js): `page.route()` a fake same-origin `http://127.0.0.1:5190/test.html` (use 127.0.0.1, `localhost` doesn't connect), then `import('/mods/...')` in `page.evaluate` with stubbed opts. `playwright-core` only resolves from inside the repo (ESM ignores NODE_PATH): symlink `node_modules` into the scratchpad or run from the repo.
- Another session may have uncommitted edits in shared files (history.md, CLAUDE.md). To commit only your own line: `git show HEAD:<file> > tmp`, append your line, `git update-index --cacheinfo 100644,$(git hash-object -w tmp),<file>`, then commit; the working tree keeps everyone's edits. The index is shared too: a file staged and left there goes into whichever session commits next (2026-10-18, the Prismatic Punch / Dam-A-Nade work landed in the RADIO commit ce9df06), so stage and commit in one command, or build the commit from a temporary index (`GIT_INDEX_FILE=$tmp git read-tree HEAD`, add, commit).
- BO1 (base game) is installed via Steam; OpenAssetTools is built at `~/.local/opt/OpenAssetTools`. `.tools/build_wonder_weapons.py` builds extra wonder weapons from it into `mods/wonder-weapons/` (git-ignored assets; see `weapons.md`).
- Blender 5.2.2 (portable, `~/.local/bin/blender`) builds the terminal booth: `.tools/build-terminal-booth.py` (about 14 min per variant with the bake).
- KTX-Software 4.4.2 (official release, `~/.local/opt/ktx-software`, run with `LD_LIBRARY_PATH=lib`) encodes the KTX2 textures (`.tools/build-ktx2.mjs`).

## Rules that bite if forgotten

- **Visual checks go on the real GPU** (GTX 1660 Ti): `--use-angle=vulkan --enable-gpu --ignore-gpu-blocklist`. SwiftShader hides beam/bloom artefacts and draws points tiny. Check point sizes by maths.
- **Lighting**: never toggle a light's `.visible` (it recompiles every shader). Pool size is baked into shaders, so only resize it on a quality change. **Rebake** `baked-light.bin.gz` (`.tools/bake-lighting.mjs`) and `sunshafts.json` (`.tools/bake-sunshafts.mjs`) whenever fixtures or light sources change.
- Don't set `needsUpdate` on texture swaps (forces a program rebuild). Compile and upload during loading, not on the first played frame. Objects that only appear mid-game go in `host.warmObjects`, and late material changes belong in a `warm` handler, so the engine's `warmShaders()` builds them while loading (performance.md).
- Don't upload every weapon's HD textures up front (it fills VRAM). Preload only targeted ones.
- **Navmesh cache** (`custom-world.js`, 2026-10-29): a custom map's navmesh is kept in IndexedDB (`kino-navmesh`), keyed by its collision triangles, traversal links, cell size and headroom; changing the other `generateTiledNavMesh` settings needs `NAV_CACHE_VERSION` bumped or the old mesh keeps loading. Anything that appears mid-game must be in the warm-up (`host.warmObjects`, or hidden in `viewScene`) before `warmShaders` runs: a mod that loads models asynchronously must await them in its setup (Nuketown's zombies compiled at the first spawn: 2-3 s a program on D3D11). Mod setups over 250 ms print as `[mods] slow setups`.
- **Warm-up waits (2026-10-29)**: `warmShaders` runs after `pendingModels()` (every `loadModel` promise, animation.js) and `host.pending`; a mod must still await its own loads in setup (Der Eisendrache's zombies and gibs do now). Hitch entries in the perf log carry `tex n/KB/mip` (GL uploads in that frame) and `ev ...` (events of the 1.5 s before); `?texLog` records every upload with its caller in `kinoTexLog`. Per-map scripted matches: `MAP=<id> node scratch/perf2/map-match.mjs` (one page at a time on the GPU; explore-only maps hang it).
- **Mid-game texture uploads (2026-10-29)**: a texture an effect clones per use (fx sprites, the Thundergun streaks) must be `renderer.initTexture`d once loaded and never disposed, or three deletes the GPU copy with the last clone and re-uploads it (1-4 MB, a hitch) on the next effect; mod textures loaded with `TextureLoader` should push a promise on `host.pending`. The warm draw uses 1x1 stand-ins only for the view scene's hidden objects; hidden world objects (culled batches, props waiting to appear) upload their real textures at load. `MAP=<id> node scratch/perf2/map-tex.mjs` lists GPU texture allocations after the start (performance.md).
- **Viewmodel light**: on maps other than Kino/Moon the first-person lights follow the map's irradiance at the camera (`kino.vmLight`, lighting.md); a map that looks too bright or dark on the gun is tuned there (the gain curve), not by changing the scene lights.
- **KTX2**: textures under `textures/` are served as GPU-compressed copies from `export/web/ktx2/` (git-ignored). After adding or changing textures there, rerun `node .tools/build-ktx2.mjs` or the old copy keeps being served (materials.md).
- Colliders pushed onto `world.dynamic` need `.box` unless `window:true`, or `world.setDoors` crashes.
- Don't publish ripped or third-party game assets. The user supplies downloads: yt-dlp is blocked for me by the classifier, so give the user a command with the output template quoted (`-o "$HOME/Downloads/name.%(ext)s"`).
- **Mod order matters** (`mods/mods.json`): `weapon-levels` must load before `progression`, or the starting gun is built before attachments apply. 16 mods are **core systems** (`CORE_MODS` in `mod-loader.js`): always loaded even if dropped from mods.json; keep the two lists in the same order (core.md).
- **Profile saves**: `kino.mods.progression` is shared. Any code that saves a cached copy must take `weaponXp`/`attachments`/`camo`/`rewards` from storage first, or it wipes weapon XP, camo progress and map rewards (the Cheese Cube camo was lost this way, 2026-10-06).
- **Attachments**: BO1 viewmodels carry every attachment, hidden by `hideTags`. Read availability from the *pristine* `hideTags` (applying attachments un-hides tags). Viewmodels are cached, so re-show bones on equip. Surfaces share one vertex buffer, so iterate a mesh's **index**, and treat a mesh as hidden when its dominant bone chain is scaled ~0. Some Pack-a-Punched guns show extra parts natively (the Commando's dual mag, the PM63's extended mag): compare against the stock base/upgrade `hideTags` before treating a part as attachment-added.
- Materials are shared between copies of a model: per-mesh changes (hiding dot cards) must not be skipped by a per-material "already patched" check, and temporary material changes (Gunsmith pulse) must be restored.
- **Rind installs** (`.tools/install-manifest.mjs`, `GET /api/install/melon-zombies`): only redistributable files are installed on players' PCs; code is picked up automatically, but new *own* data or assets (not from BO1/BO3 or other third parties) need a rule in its `OWN` list, and anything ripped or third-party must never match it.
- **Der Eisendrache placed props** (`mods/der-eisendrache/merge-props.js`): pieces of repeated props and window boards are drawn as InstancedMeshes; the original meshes stay in place on no render layer (`layers.mask = 0`) and the instances copy their nodes' matrices and visibility each frame. Move or show a placed prop through its node (position, `visible`), never by editing its meshes' materials or visibility, and call `updateMatrixWorld(true)` after moving it (the map root doesn't auto-update). The map's version query (`maps.json` `?v=`) must be bumped on every rebuild; build with `--tex 512 --prop-tex 256` or the textures are regenerated.
- **Static freeze (whole scene, 2026-10-17)**: every object in the scene is frozen at load (`static-freeze.js`), all-static subtrees are skipped by three's matrix walk, and the scene root no longer composes its matrix. A node a mod moves thaws within two frames; `updateMatrix()` then `updateMatrixWorld(true)` after a move makes it immediate. Exception: a custom map's own nodes come out of `optimizeStaticScene` with `matrixAutoUpdate` already off, and the freeze never thaws those: under `world.root` call `updateMatrix()` yourself, or turn `matrixAutoUpdate` back on at the mod's setup as Der Eisendrache does for its CASTLE_ subtrees (2026-10-22). Bones with nothing attached are `visible = false` (`hideBones`): attach things to bones with `bone.add`/`attach` (the chain re-shows itself), never by re-parenting around it.
- **Der Eisendrache instanced pieces leave the scene graph** (merge-props.js, 2026-10-17): a mod that needs a placed prop's meshes by traversal after the mod's setup (the gondola gates' colliders) must have its node prefix in merge-props `SKIP`; moving or showing a node still works (instances follow their parent node).
- **Player collision caches nearby triangles** (collision-world.js): after editing the collision geometry at runtime, call `world.collision.invalidateCache()` (the booths do after clearing debris); `useCache = false` gives the plain BVH walk for A/B tests.
- **Post chain (2026-10-22)**: `mods.renderWorld(scene,cam,{viewScene,viewCamera,drawView})` returns true when the lighting mod drew the viewmodel inside its composer (after AO, before bloom and the grade); the engine then skips its own draw. The grade pass replaces OutputPass (tone mapping + sRGB live there now); per-map looks in `GRADES` (`mods/lighting/grade.js`) or a map entry's `grade`; tune live with `kino.post.set({...})`. Settings `filmLook`/`filmGrain`. Low graphics has no composer, so no grade. The haze pass also applies the fires' heat shimmer (`kino.heatScene` drawn to `heatRT`, read as `tHeat`; lighting.md Fire).
- `kino.debug.lookAt` wants an array (`[x, y, z]`); a Vector3 makes the camera NaN, and the movement mod's camera feel then poisons every later frame (it now reports once and recovers).
- Benchmarks: `node .tools/bench-castle.mjs high` (Der Eisendrache, every area) and `.tools/bench-fps.mjs` (other maps); `--profile out.cpuprofile` + `node .tools/profile-summary.mjs out.cpuprofile`. Hold one page open on the GPU for repeated checks with a `--remote-debugging-port` Chromium and `chromium.connectOverCDP` (session scripts, not in the repo). The 6 GB card is shared: another session's browser or a leftover Electron game runtime loses the WebGL context mid-load (`Context Lost` in the console = an invalid run).
- **First-person motion is `mods/movement/fp.js`** (2026-10-19): the engine's own bob is off there (`view.bobScale = 0`, animation.js) and every sway, lag, bob, kick and the framing live in that file, scaled by `weaponWeight(def)` (class table; `def.weight` overrides) and Settings → Weapon motion (`settings.gunMotion`). Third-person held models: `def.worldScale` (imported BO3 world models default to 1/2.2 in `holdWeapon`), textures restored with `restoreImages` (texture-memory.js) because world models share image sources with the viewmodels and draw black otherwise; the characters mod tints a BO3 weapon's own viewhands for characters without an arms rig. Third-person lean goes through `pose({lean:{x,z}})` on BO1 rigs only: the procedural rigs' `pose()` takes numbers, an object there made the body NaN. Update the viewmodel from `view.pivot.updateMatrixWorld(true)`, never `view.root`: three's `getWorldPosition` no longer refreshes parents, so a root update composes against the pivot's stale world matrix (the IK then blends from last frame's wrist). The bob is paced by distance with a stride of 150-200 units per figure-8 (two steps); smaller strides shake. Sprint is procedural for every rig (`view.sprintPose`, animation.js; the sprint clips never play); the camera's share of the motion goes through `kino.fpMotion.cam` and the engine's `mods.fovOffset`.
- **Reflex sights and the motion layer** (2026-10-19): the scopes mod runs before fp.js and aligns the sight from the engine's pose, so anything fp.js adds at full aim moves the sight off the fixed dot: hip poses are scaled by (1-aim)² there, and the dot waits for `align.err` < 0.007 rad. Operators without their own model get their arm set re-skinned onto imported rigs (`ArmSetArms`; debug handles `kino.fpArms` / `kino.fpArmsSet`). A profile edit made in a running game page is overwritten at `pagehide` by the progression mod's in-memory save: in a test, write it from a Playwright `addInitScript` and reload. Never `open(p,'w')` before reading p in a one-liner: it truncates the file first (this bit CLAUDE.md once; restored from a transcript).
- **Testing as an operator on the hosted page**: write `profile.character` from a Playwright `addInitScript` and reload (a plain write is overwritten at `pagehide`); grab frames from `renderer.domElement.toDataURL` inside a rAF rather than `page.screenshot`, which stalls for minutes while the user plays on the same GPU, and keep the headless page short-lived: two games on the 1660 Ti hit `GL_OUT_OF_MEMORY` and the page then sticks in `raise` with black frames (reload it).
- When adding a system, add its detail to the matching `docs/fork/*.md` file and a one-line entry to `history.md`. Keep this file short.
