# Menu, profile, mod loader, settings, keybinds

- **Main menu** `export/web/home.{html,css,js}` is served at `/` via `KINO_HOME=home.html` (env var read by `.tools/serve.mjs`, set in the quadlet). Kino itself is `/index.html`. Tabs: Play (map browser from `mods/maps.json`), Loadout (weapon thumbnails rendered from world models, stats, bonuses), Character (3D preview), Mods. `maps.html` just redirects to `./#play`.
- **Profile** `profile.js`: shared localStorage profile (`kino.mods.progression`: xp, level, loadout, character, stats), plus unlock rules read from `mods/progression/progression.json`. The menu and the progression mod both use it.
- **Mod loader** `mod-loader.js`: `ModHost` merges data patches (objects merge, arrays replace, `null` deletes, `{add,remove}`, weapon `"extends"` which also sets `baseId`), calls an optional `prepare(data)` from scripts, wraps session/enemies methods to emit events, then runs `setup(api)`. `host.camera` and `host.hideViewmodel` let a mod take over rendering.
- **Settings**: `settings.js` (localStorage `kino.settings`: sensitivity, ADS sensitivity, invert Y, FOV, volume, render scale, FPS counter; `renderSettings()` builds the form). `game-menu.js` + `game-menu.css` add Settings and Main menu buttons plus a settings overlay to any game page's `#menu`, and apply volume, render scale and FPS; sensitivity and FOV are read directly in the loops. The main menu has a Settings tab.
- **Dev settings**: `FIELDS` entries with `group:'dev'` render inside a collapsed `<details class="settings-dev">`. `devConsole` (default off) gates the cheat console's ` key; the pause-menu CONSOLE button was removed.
- **Keybinds**: `settings.binds` holds only the changed keys; `ACTIONS`/`DEFAULT_BINDS` are in settings.js. game-menu.js remaps in the capture phase: a rebound key is re-dispatched as the action's default `code`, and a default key whose action moved elsewhere is swallowed. The game loops are untouched.
- **Loadout picker** (2026-10-01, BO7-style; since 2026-10-14 the starting slot is pistols only and the class tabs are used by the Mystery Box list's rarity tiers): weapon slots show class tabs (`CLASSES` in home.js: Assault Rifles, SMGs, Shotguns, LMGs, Snipers, Pistols, Launchers, Specials, mapped from `weaponClass()`), each with `unlocked/total`. The grid shows one class, opening on the class of the gun in the slot (remembered per slot in `activeClass`). Cards are bigger, with badges for weapon level (`LV n` / `MAX`) and camos unlocked (`CAMO n/6`).
- **Tactical slot** (2026-10-01): `progression.json` `tacticalLevel` 6 and `tactical` [{id, name, description, level}]: Monkey Bombs 6, Gersh Device 22, QED 33. `unlocks()` gains `tactical`/`tacticalSlot`, and `validLoadout()` returns `tactical`. The menu has a TACTICAL slot (with thumbnails from `data.equipment`, which the menu now carries; `renderTactical` is its detail panel). In game the progression mod gives it on load and every new game: `session.giveMonkeys()` or `window.kino.tactical.give(id, quiet)` (moon-equipment). Winter's Howl (`freezegun_zm`) is unlocked at level 49 and appears under Specials.
- **Pistol start, first kit, rarities and the Mystery Box list** (2026-10-14, roadmap Phase 1, user's rules): **one** starting weapon slot, pistols only (`isPistol` = `weaponClass()==='Pistol'`); `validLoadout` drops anything else (an old SMG primary or any secondary) to the M1911 and always returns `secondary:''`. `progression.json` weapons: base BO1 guns (every gun in game-data.json, Ray Gun and Thundergun included) have `kit:true` and are owned from level 1, and their `gunsmith` level (their old unlock level) opens them in the Gunsmith; every other gun has `level`, which unlocks the gun and its Gunsmith together (`unlockLevel`, `gunsmithLevel` in profile.js). Gated in the menu (`smithOpen`: no GUNSMITH button or panel, the detail says "Gunsmith opens at level N"; the ◀ ▶ list skips locked guns) and in the pause menu (weapon-levels mod). Every weapon, tactical and lethal has a `rarity`; `rarities` lists the tiers with colour and box weight: Common 1.3, Uncommon 1.2, Rare 1, Epic .85, Legendary .7, Wonder Weapon .55 (its own top tier). `lethal`: Frag Grenade (refills grenades to 4) and Claymores, both level 1, off by default. **Box list**: the MYSTERY BOX card in the Loadout pane, with rarity tabs then TACTICALS and LETHALS, ALL ON/ALL OFF, unlimited per tier. Each weapon tier has a minimum switched on (`box.minPerTier`, user's numbers 2026-10-14: Wonder 1, Legendary 1, Epic 3, Rare 3, Uncommon 4, Common 4; or every unlocked gun of the tier if fewer, `boxMin`): `boxItems` tops a short tier up in list order (`forced`), the menu writes those to `boxOn` on the next change and blocks switching a tier below its minimum. Any unlocked item can go in, wall guns too; locked ones show with their level. Stored as overrides `loadout.boxOn`/`boxOff` against the game's `boxPool` (`boxItems`, `setBoxItem`), so newly unlocked box guns join by default. In game the progression mod defines `window.kino.boxList` (a getter: `allowed`, `weight`, `extra` for switched-on non-pool items, `owned`: frag at 4 grenades, claymores held). `mystery-box.js` `start()` reads it on every roll: the player's items minus what they hold, rarity-weighted; if nothing is left it rolls the full pool. Items the list doesn't know (a map's own box items) pass. Box rolls are local to the player who pays, so in co-op each player gets their own list. The mod also wraps `session.giveWeapon` for the two lethals and loads their box models. Verified headlessly: SMG primary → M1911 start, a 4-item list rolled 6000 times matched the weights, an empty list fell back to the full pool, Moon honours the list, Python at level 12 shows "Gunsmith opens at level 30".


## Armory (2026-10-01)

The menu's Loadout, Classes and Character tabs are one **Armory** tab with panes (`#armory-nav`, `.pane`): Loadout, Classes, Operator (the character picker, renamed). `showTab()` maps pane names and old links (`#loadout`, `#classes`, `#character` → operator) to the Armory and remembers the last pane; the 3D stage only runs while the Operator pane is showing.

**Weapons pane** (2026-10-14): Armory → WEAPONS lists every gun in `progression.json` by its class (`CLASSES` tabs, `unlocked/total`), with rarity, weapon level, camo and IN BOX badges; locked guns show their level. The detail (`renderDetail` with `{el, smith:true}`) carries the Gunsmith whenever that gun's Gunsmith is open (`openLoadoutGunsmith(id, onClose)` returns to the pane), SET AS STARTING PISTOL for pistols, and ADD TO / REMOVE FROM MYSTERY BOX (`toggleBoxItem`, which keeps the tier minimums). `renderLoadout()` ends with `renderWeapons()`, so both panes stay in step. Also fixed: the career page's `.stat` tile style was global and turned the loadout's stat bars into boxes; it is now `.stat-grid .stat`.

## Controller (mods/controller, 2026-10-02)

Gamepad API polled every animation frame (also while paused, so Start resumes without pointer lock via `api.setActive(true)`; on game over it resets first). Left stick → `kino.gamepad.move` {forward, strafe}, read by game.js/zombies.js next to the touch values (analog walk speed); right stick → `camera.rotation` (deadzone .15, squared response, 3.4 rad/s × sensitivity, ½ × ADS sensitivity while aiming, invert Y honoured). Every button is sent as the key or mouse event the game and mods already handle: RT/LT = mouse buttons 0/2 on the canvas; A Space, B KeyC (tap crouch, hold prone, slide while sprinting), Y KeyQ, LB KeyX (tactical), RB KeyG (hold to cook), R3 KeyV, L3 latches ShiftLeft (sprint) until the stick is let go or you aim, D-pad up/left/down/right Digit4/Digit5/KeyZ/KeyT, Back KeyT, X = KeyF held while a use prompt shows (buy/repair) else a KeyR tap. Synthetic keys carry the default codes with `remapped=true` (the keybind remapper passes them) and are dispatched on `document.body`: on `window` itself the game's own window listeners (registered first) ran before the mods' capture listeners at the target phase, so one RB tap threw two grenades. Rumble on damage and a light kick per shot (`vibrationActuator.playEffect`). `body.using-pad` swaps the prompt's `F` glyph for `X`. The classes mod now listens for the default `KeyZ` (the remapper re-sends rebound keys as defaults). Not done: menu navigation with the pad, aim assist.

## Career (2026-10-02)

`mods/career` records lifetime stats in `kino.mods.career` (cloud-synced; seeded once from the profile's kills/games/best round): totals (kills, headshots, knife and hellhound kills, rounds survived, highest round = round reached, games, deaths, points earned, shots, time, perks drunk, Pack-a-Punches), per map (`kino`, or the custom map id from `zombies.html?map=`; Moon loads no mods so isn't recorded) and per weapon (kills, headshots, shots, time held, Pack-a-Punches). Kill credit comes from the last damage cause per enemy (`beforeEnemyDamage`): melee → knife, turret → sentry_turret, gersh, electric → trap, explosion → the launcher in hand or else frag_grenade_zm, otherwise the gun in hand. Cheat games and co-op remote kills are skipped. Saved every 5 s and on pagehide. Menu: CAREER tab (`career-view.js`): Overview cards + favourite weapon/most played map, Maps (list + detail), Weapons (search, sort by kills/time/headshots, detail).

## Engine and maps (2026-10-02)

The user asked for the website to be the core and maps to be maps, not separate games. `play.html?map=<id>` runs `engine.js`, which owns the renderer, input, player, weapons (hitscan, thundergun, projectiles, explosives, knife, grenades), enemies, power-ups, perk drinks, the Mystery Box, Pack-a-Punch, barricades, rounds, the HUD, the debug API (`kino.debug`) and mods. It reads `mods/maps.json`, imports `maps/<entry.module ?? (entry.dir ? 'custom' : entry.id)>.js` and calls `createMap(ctx, entry)`. `ctx` exposes THREE, scene, camera, renderer, audio, lights (ambient/hemi/keyLight/fill), keys, `shop` (shared wall-buy/perk/box/Pack-a-Punch/power actions and prompt texts) and getters for data, world, session, player, enemies, view, features, mysteryBox, powerups, perkDrink, plus toast/announce/effect/damage/equipView/moveTo/flash/collect/clearInput.

A map returns: `loadData()`, `loadWorld(progress)` (an object with physics, raycast, lineClear, path, closest, barriers, setDoors, setBoards, reset...), `spawn()`, `createFeatures(opts)`, `findPrompt(camera)` → {target, text, distance}, `interact(target)`, `boardCount(b)`, and optional hooks: `Session`, `Enemies`, `createMysteryBox`, `perkInfo`, `player` (controller options), `ready`, `update`, `prePlayer` (return true to skip movement), `onKill`, `dropAllowed`, `brokenWindows`, `onPowerup`, `beforeDamage` (return false to ignore), `onShot(ray, far, kind)`, `fire(def, forward)` (map weapons), `gravityAt`, `viewDef`, `blocked`/`hideViewmodel`, `announceRounds`, `roundText`, `hudEffects`, `location`, `objective`, `keydown`, `beforeReset`/`reset`, `state`, `debug` (merged into kino.debug), `bestKey`, `shotRange`, branding (`title`, `announceTitle`; entries add `tagline`, `place`, `kicker`).

- **maps/kino.js**: upstream game.js's Kino parts (raw BO1 entity prompts, stage teleporter and projection room, hidden film rooms via KinoFeatures, electric traps, meteors, gas crawlers, Kino fog/exposure).
- **maps/custom.js**: the fork's zombies.js parts (CustomWorld, MapFeatures, traps, teleporters with return trips, shootable Easter eggs, hellhound fog). Exports `MapFeatures`.
- **maps/moon.js** (+ `maps/moon.css`): upstream moon.js + moon-combat.js. MoonMapSession (MoonSession + busy/weaponUnavailable; the attachment key toggles the Zap Guns), MoonEnemies, a world adapter over collision + moving parts + MoonNavigation, MoonFeatures/MoonPresentation driven through a `combat` shim built from engine parts, the engine's audio object upgraded to MoonAudio (`Object.setPrototypeOf`), environment (gravity, air, P.E.S.), Area 51 ↔ Griffin Station teleports (relocate → session.enterArea), Wave Gun / Zap Guns via `fire`, Gersh/QED thrown with X, low-gravity grenades, Moon HUD panel (gravity, power, P.E.S., oxygen, visor, equipment, digger alarms, Tab journal). Keys: P = P.E.S. (Q is the weapon swap), H = hack, Tab = journal, 3 = Mule Kick slot. Gotchas: Moon's combat data has no `entities` (Kino's reel events read them, so it's set to []); the player's fall reset must be below No Man's Land (y≈-680). The old explore mode with destination shortcuts is gone (`kino.debug.relocate(name)` remains).
- Mods: the engine passes every map's entry as `api.map` (Kino included), so mods that detected Kino by `!api.map` now check `api.map.id==='kino'` (lighting, map-materials); `mod.json` `maps`/`skipMaps` filter mods per map (lighting, moon-weapons, moon-equipment skip Moon; map-materials is Kino-only).


### Moon performance notes
- `maps/moon.js` instances repeated static props in 4096-unit cells (`optimizeStaticScene`; 1024 gave ~1000 tiny batches) and distance-culls small static meshes (radius × 90, at least 1500) by switching them off render layer 0. It never touches `.visible`, which the Moon features own. Culled meshes also drop out of shadow passes and layer-0 raycasts; no Moon gameplay raycasts the scene.
- Pack-a-Punch: `KinoFeatures.syncPack` asks the map for its machine (`packMachine()`); Moon's comes from its own entity data. Before that, the lookup threw every frame on Moon and froze the game after paying.
- **Settings tabs (2026-10-05):** `renderSettings` (settings.js) builds a tab strip (GRAPHICS, AUDIO, CONTROLS with the key bindings, GAMEPLAY, DEV). Each field has a `tab`. The last tab is remembered in `kino.settings.tab`. Used by the main menu and the in-game overlay; styles in game-menu.css.
- **Frame rate cap (2026-10-05):** `fpsCap` is a number (frames a second, 0 = none; was a 30 FPS toggle, migrated: true→30). The slider runs 15–240 with a last stop of Unlimited (`toInput`/`fromInput`). Fields with `typed` let you click the value and type a number (Enter/blur applies, Esc cancels, empty or 0 = off, clamped 5–1000). engine.js frames at 1000/cap.
- **Box odds (2026-10-15, user: "it seems a bit hard to get rarer weapons")**: the rarity weights in `progression.json` are per gun, so a tier's share is (guns in it) × weight. They were Common 1.3 → Wonder 0.55 (Legendary ~8%, Wonder ~6.5% of spins with the full list); now Common .8, Uncommon .9, Rare 1, Epic 1.15, Legendary 1.5, Wonder 1.4: about 5.6 / 8.9 / 29.5 / 27.5 / 14.8 / 13.8% with every gun on (switching guns off in the box list changes the shares).
- **Box odds, second pass (2026-10-15, user: "a bit rarer than the new odds")**: Legendary 1.5 → 1.05, Wonder 1.4 → 0.85: about Common 6.2 / Uncommon 9.8 / Rare 32.7 / Epic 30.5 / Legendary 11.5 / Wonder 9.3% with every gun on (originally ~8% / ~6.5%, first pass ~15% / ~14%).
