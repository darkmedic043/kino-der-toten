# Map materials and HD textures

- **Kino map materials** (`mods/map-materials`, Kino only): normal maps: the export attached none, but 400+ ship in `textures/` in DXT5nm layout (X in alpha, Y in green). `.tools/build-kino-normals.py` converts the matched ones to standard RGB normal maps in `textures/nrm/*.webp` (236 files, 7.6 MB) and writes `normals.json` (material name → map); the mod loads them after start with normalScale (1, −1) and max anisotropy on colour maps. The theatre chandelier's opaque slot also holds bead and crystal cards, so an `onBeforeCompile` discard cuts alpha < .45 only where fract(uv.x) < .49 (the frame half has zero alpha too). the map export lost blend modes. Glass (`global_glass*`, `dec_glass01`, lightning chamber glass, plus model glass like `mtl_glass_v2_off`) was a 0.45 alpha cut-out, so clear panes vanished and frosted ones went solid; it is now alpha-blended with depthWrite off. Dark-on-white stains (burntstain, darkstain, grime, scorch, pipe stain, blast crater) use MultiplyBlending with polygon offset; soft decals (blood, cracks, puddles, `*_blend`) blend instead of cutting at 0.45. `hdrportal_lighten` (an editor light portal) is hidden and `clothcable_glow` is additive. Layered `base:decal` materials (names containing ':') are left alone. It also caps the spawn-room return teleporter pad (centre 2,1274; its collision is a bowl from rim ~89–92 down to ~78) with an invisible 57-radius cylinder collider (top 89.4) pushed onto `world.dynamic`.
- **HD textures** (`.tools/upscale-kino-textures.py`, Real-ESRGAN ncnn-vulkan x4plus in `~/.local/opt/realesrgan`, runs on the GTX 1660 Ti at about 20 s per 512² texture): the 376 Kino colour textures of 128–512 px are padded with a wrapped border (for seamless tiling), upscaled ×4, cropped, and Lanczos-resized to ×2 as `textures/hd/*.webp` (42 MB). `hd.json` maps file → HD and `hd-materials.json` maps material name → HD (415 materials; rebuild with `--table-only`). The map-materials mod swaps them in one per frame after start (ImageBitmapLoader, off-thread decode) and disposes the SD GPU copy; Settings → HD textures toggles live, and phones keep the SD textures.
- **Smooth shading** (map-materials): the Kino export (compose_scene_t5.py `build_prim`) writes flat per-triangle normals. At load, vertices at the same quantised position (1/20 unit) get the area-weighted normal of the faces within 50° of their own face (in place, 917 meshes in about 0.7 s).
- **HD weapon textures** (`mods/hd-weapons`, `.tools/upscale-kino-textures.py --weapons`): 108 textures referenced by every weapon glTF (game-data plus Moon: model, worldModel, leftModel, upgrades; 128–512 px sources; the 46 2048 px upscales of 1024 px originals were dropped 2026-10-16 for video memory, see performance.md), upscaled the same way into `textures/hd-weapons/` (44 MB; names are path-unique with `/` → `__`). `hd.json` maps the web-root-relative source → HD. `prepare()` installs a URL modifier on the shared `assetManager` (runtime-assets.js), so every weapon load (viewmodels, world models, box) gets HD while `settings.hdTextures` is on; phones skip it.
- **KTX2 textures** (2026-10-17, `ktx2.js`, `.tools/build-ktx2.mjs`): GPU-compressed copies of every power-of-two image under `textures/` (2,940: the Kino map, all weapon/character/zombie models via `../textures/...`, `textures/hd`, `hd-weapons`, `nrm`), in `export/web/ktx2/<path>.ktx2` (git-ignored, ~570 MB; derived from ripped textures, so streamed, never in Rind's install) with `ktx2/manifest.json` (`path → [stamp, w, h, bytes]`; the stamp goes on the URL as `?v=`).
  - Encoding: KTX-Software 4.4.2 (`~/.local/opt/ktx-software`, official release, `LD_LIBRARY_PATH=lib`; `KTX_HOME` overrides), UASTC quality 2, RDO λ 1.0, zstd 18, full mip chain, RGBA; about 30 min for all on 6 cores, incremental afterwards. **Rerun `node .tools/build-ktx2.mjs [roots]` after changing or adding textures**, or the game keeps serving the old copy. Sources go through ffmpeg to plain RGBA PNG first: most BO1 PNGs carry `gAMA 1.0`, which Chromium's glTF path ignores but `ktx create` honours (it brightened them: PSNR 12 dB); the transfer function is *assigned* (`--assign-tf`), never converted, because three picks the sRGB or UNORM BC7 upload format from `texture.colorSpace` per material slot. `_n`/`_nml`/`_nrm`/`nrm/` files are tagged linear.
  - Quality: UASTC 46-56 dB against the source (ETC1S was 33-40 dB); screenshots against the image path 52-57 dB (gun close-up, Cheese Cube) and matching Kino views. Desktop GPUs get BC7 (`EXT_texture_compression_bptc`).
  - Runtime (`setupKtx2(renderer)` in engine.js; desktop only, phones keep their -mobile handler; `?noKtx2` turns it off): an `assetManager` handler for png/webp/jpg answers every glTF image request (after `assetManager.resolveURL`, so the hd-weapons redirect still applies): listed → `KTX2Loader` (own LoadingManager, transcoder `vendor/jsm/libs/basis/`, 4 workers), one transcode per file shared by clones (Kino: 1,198 files for 1,658 uses); not listed or failed → an `ImageBitmapLoader` texture exactly as GLTFLoader makes it. Textures come back with colour space none like an image texture; GLTFLoader sets sRGB on colour slots. `ktx2Texture(url)` does the same for code that loads its own textures (map-materials' normal maps and HD swaps; HD swaps skip `generateMipmaps` for compressed textures). `kino.debug.ktx2()` has counts.
  - Also encoded (same day, later): `mods/maps/der-eisendrache/tex` and `mods/maps/the-giant/tex` (3,774 WebP, 128 MB → 503 MB of KTX2, 27 min). Der Eisendrache VRAM 4.57 → 2.03 GB, load 83 → 76 s; its texture arrays are now compressed at native size (they were RGBA resized to 256 px). See performance.md (frame rate pass) for the batching.
  - Not covered yet: maps with their own loaders (Moon, Ascension, Shangri-La, Call of the Dead, Coast), embedded glb images (Cheese Cube), TextureLoader paths (fx, characters, camos), phones (ASTC/ETC2 would help them most), non-power-of-two images.
  - Measured on Kino (GTX 1660 Ti, desktop): VRAM 3.42 → 1.21 GB; renderer + GPU process RAM 4.54 → 3.57 GB (no decoded bitmaps; but the JS heap grows 0.6 → 1.2 GB because the transcoded mips stay in RAM after upload: freeing them, with a restore path like texture-memory.js, is a follow-up); load 23 s either way locally; FPS unchanged; downloads 213 MB / 1,531 requests → 234 MB / 1,039 (PNG sources shrink about 2x, WebP sources grow 3-7x: they are heavily lossy). `.ktx2` isn't in Cloudflare's default cached extensions, so those come from the origin through the tunnel unless a cache rule covers `/ktx2/`.
